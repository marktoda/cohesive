# Architecture

> Substrate-first agentic engineering, delivered as a Claude Code plugin. Helps a codebase remember.

This is the binding architectural map. Hook lines point at the design docs, invariants, and conventions that carry the detail. Update this file when the broad shape changes or a hook needs adjusting; let the deeper docs absorb the rest.

## Three-tier architecture

Cohesive is a Claude Code plugin organized in three implementation tiers under `${CLAUDE_PLUGIN_ROOT}`. Implementation is what *plugin users get*; substrate is contributor-facing rules about *this repo itself*.

- **`skills/`** — workflow orchestration. The session-start orientation skill (`using-cohesive`), the router (`cohesively`), the adoption skill (`init`), and the workflow subskills enumerated in [`docs/substrate/architecture/skills.md`](docs/substrate/architecture/skills.md) together make up the user-facing surface. Each skill is a process; skills do not run reviews directly. The `implement-cohesively` skill is the only one that produces code, and it does so by composing `superpowers:executing-plans` once per implementation pass rather than writing code directly. The per-skill design layer above the SKILL.md bodies lives at [`docs/substrate/architecture/skills.md`](docs/substrate/architecture/skills.md); chain-transition contracts at [`docs/substrate/architecture/handoffs.md`](docs/substrate/architecture/handoffs.md).
- **`agents/`** — fresh-context reviewer agents. Dispatched via the Task tool with explicit input paths. They do not inherit conversation context; each review runs in a clean subprocess.
- **`references/`** — runtime methodology cited by skills and agents during the workflow: the rubrics (`cohesion-rubric.md`, `architecture-review-rubric.md`), the design pressure-test battery, the locality-over-centralization principle, the substrate model, the chat-render voice guide (`output-voice.md`), and `templates/` — fillable forms skills consume to produce artifacts. All shipped to plugin users.

The fourth layer — substrate at `docs/substrate/**` — governs *this codebase*. Contributor-facing: cross-cutting architecture decisions in [`architecture/`](docs/substrate/architecture/) (three-tier separation, composition with Superpowers, fresh-eyes review property, the per-skill design layer in `skills.md`, chain-transition contracts in `handoffs.md`); prescriptive component rules in [`conventions/`](docs/substrate/conventions/) (skill-shape, reviewer-agent-shape, dispatch-protocol template, substrate-layout, audience-separation, **scope** — what Cohesive does and doesn't do); plus this repo's named invariants, gotchas, and matrices. History at `docs/history/**` carries workflow products, plans, and transcripts.

The split (contributor-facing substrate vs user-facing implementation) is the load-bearing structural decision. → see [`docs/substrate/architecture/three-tier-architecture.md`](docs/substrate/architecture/three-tier-architecture.md).

## Composition over reinvention

Cohesive composes with [Superpowers](https://github.com/obra/superpowers) rather than reinventing implementation discipline:

- Worktrees come from `superpowers:using-git-worktrees` (loose composition with a 5-line inline fallback when Superpowers is absent).
- Per-pass plan-writing comes from `superpowers:writing-plans` and per-pass TDD execution comes from `superpowers:executing-plans`, both invoked once per implementation pass from inside `implement-cohesively` (tight composition with no fallback; Superpowers is required for the implementation pass).
- Branch finishing comes from `superpowers:finishing-a-development-branch` (user-invoked after `implement-cohesively` Implemented verdict).

Cohesive owns substrate and substrate-shaped framing (thin intent paragraph + delta-size budget gate + end-of-run dual reviewer dispatch); Superpowers owns per-pass plan writing and TDD execution. The seam between the two is documented and intentional. → see [`docs/substrate/architecture/composition-with-superpowers.md`](docs/substrate/architecture/composition-with-superpowers.md).

## Fresh-eyes review

Reviewer agents run in isolated subprocesses with no conversation-context inheritance. The dispatching skill passes inputs as explicit file paths; the agent system prompt forbids reading prior conversation. This is the load-bearing safety property of every Cohesive review — without it, reviews degrade to performance. The harness's Task-tool isolation provides the structural fence; the agent-file preamble is convention reinforcement. → see [`docs/substrate/architecture/fresh-eyes-review.md`](docs/substrate/architecture/fresh-eyes-review.md) for the property; [`docs/substrate/conventions/dispatch-protocol.md`](docs/substrate/conventions/dispatch-protocol.md) for the prescriptive contract.

## Substrate

Current canonical substrate lives under `docs/substrate/`:

- **[`architecture/`](docs/substrate/architecture/)** — cross-cutting architecture decisions read when changing the system shape. Houses [`three-tier-architecture.md`](docs/substrate/architecture/three-tier-architecture.md) (skills/agents/references separation), [`composition-with-superpowers.md`](docs/substrate/architecture/composition-with-superpowers.md) (Cohesive↔Superpowers seam), [`fresh-eyes-review.md`](docs/substrate/architecture/fresh-eyes-review.md) (the load-bearing review property), [`skills.md`](docs/substrate/architecture/skills.md) (per-skill design layer with one section per skill), and [`handoffs.md`](docs/substrate/architecture/handoffs.md) (chain-transition contracts).
- **[`conventions/`](docs/substrate/conventions/)** — prescriptive component rules read when authoring. Houses [`skill-shape.md`](docs/substrate/conventions/skill-shape.md) (canonical SKILL.md shape, including the §"When to edit SKILL.md alone, and when to edit the design layer first" rule), [`reviewer-agent-shape.md`](docs/substrate/conventions/reviewer-agent-shape.md) (canonical reviewer-agent shape), [`dispatch-protocol.md`](docs/substrate/conventions/dispatch-protocol.md) (the **Task-tool** dispatch-prompt template enforcing fresh-eyes-review), [`skill-tool-dispatch.md`](docs/substrate/conventions/skill-tool-dispatch.md) (the **Skill-tool** dispatch contract for skill→skill composition), and [`substrate-layout.md`](docs/substrate/conventions/substrate-layout.md) (where artifacts live).
- **[`invariants/`](docs/substrate/invariants/)** — named global rules with structural enforcement. v0.1 ships these: `PLUGIN_ROOT_PATHS` (every internal path uses `${CLAUDE_PLUGIN_ROOT}`), `VERDICT_BEFORE_EVIDENCE` (every verdict-led skill's Output format block opens with `**Verdict:**` within the first three non-blank lines), `IMPLEMENTATION_PLAN_COVERS_DELTA` (every entry in a design delta ledger is covered by the single per-pass plan; end-of-run dual reviewer dispatch with AND-shape verdict synthesis required), and `SKILL_DESIGN_DOC_SECTION` (every directory under `skills/` has a `### <name>` section in `architecture/skills.md`). `PLUGIN_ROOT_PATHS`, `VERDICT_BEFORE_EVIDENCE`, and `SKILL_DESIGN_DOC_SECTION` are mechanically enforced by `scripts/validate_plugin.sh`; `IMPLEMENTATION_PLAN_COVERS_DELTA` is enforced by `implement-cohesively`'s skill-body acceptance criteria and `delta-coverage-reviewer`'s verdict, with a deferred CI grep for commit-message citations.
- **[`gotchas/`](docs/substrate/gotchas/)** — documented scars. Each names a symptom, a tempting wrong fix, and the correct pattern.
- **[`matrices/`](docs/substrate/matrices/)** — branchy behavior written down as cells with stable IDs. The router behavior matrix and the artifact-placement matrix (where artifacts live, what their lifecycle is) live here.

Workflow products (reviews, design delta ledgers, transcripts) and retired historical docs live under [`docs/history/`](docs/history/).

## Conventions

- **Skill shape** — required body sections, frontmatter shape, output format, router announcement form, clarifying-question discipline, recommended-next-skill output blocks, anti-patterns, and §"When to edit SKILL.md alone, and when to edit the design layer first": [`docs/substrate/conventions/skill-shape.md`](docs/substrate/conventions/skill-shape.md).
- **Reviewer agent shape** — required sections, the canonical fresh-eyes preamble: [`docs/substrate/conventions/reviewer-agent-shape.md`](docs/substrate/conventions/reviewer-agent-shape.md).
- **Dispatch protocol** — the dispatch-prompt contract every reviewer-dispatching skill follows: [`docs/substrate/conventions/dispatch-protocol.md`](docs/substrate/conventions/dispatch-protocol.md).
- **Skill-tool dispatch** — the contract for skill→skill composition (`validate-rewrite`'s repair loop, `implement-cohesively`'s end-of-run review-diff dispatch): [`docs/substrate/conventions/skill-tool-dispatch.md`](docs/substrate/conventions/skill-tool-dispatch.md).
- **Substrate layout** — where artifacts live (delta ledgers, reviews, brainstorms, plans): [`docs/substrate/conventions/substrate-layout.md`](docs/substrate/conventions/substrate-layout.md).
- **Audience separation** — chat trailers carry decision-shape vocabulary; persisted files carry substrate-shape vocabulary; the surface-by-surface translation rule for verdict labels and substrate types: [`docs/substrate/conventions/audience-separation.md`](docs/substrate/conventions/audience-separation.md).
- **Scope** — what Cohesive does and explicitly doesn't do; the negative-space discipline ("overbuild simplicity and extensibility; underbuild everywhere else") and the promotion criteria for new substrate: [`docs/substrate/conventions/scope.md`](docs/substrate/conventions/scope.md).
- **Output voice and density** — chat-render rules (verdict-leads, header-depth cap, density budgets, forbidden phrasings, faithful-subset-of-persisted-file): [`references/output-voice.md`](references/output-voice.md). Loaded at chat-render time via a body-level imperative in each non-router skill and reviewer agent (the imperative literal lives in body prose, never in render templates — see [`docs/substrate/gotchas/style-guide-rot.md`](docs/substrate/gotchas/style-guide-rot.md) §"Correct pattern"). Companion worked transcript at [`docs/history/transcripts/output-voice-worked-example.md`](docs/history/transcripts/output-voice-worked-example.md).
- **Path discipline** — every internal reference uses `${CLAUDE_PLUGIN_ROOT}/...`. Enforced by [`PLUGIN_ROOT_PATHS`](docs/substrate/invariants/PLUGIN_ROOT_PATHS.md).
- **Verdict discipline** — every verdict-led skill leads with the verdict. Enforced by [`VERDICT_BEFORE_EVIDENCE`](docs/substrate/invariants/VERDICT_BEFORE_EVIDENCE.md).
- **Source-of-truth hierarchy** — this doc is binding for current architecture. The README §"What's in the box" is derived from this doc and from on-disk reality. The historical plan at [`docs/history/plans/2026-05-04-mvp-implementation.md`](docs/history/plans/2026-05-04-mvp-implementation.md) is preserved as the dated artifact that drove v0.1; not authoritative for current state.
- **Default artifact dir for Cohesive run against external repos:** `docs/cohesive/<x>/` with detection of existing repo conventions (`docs/design/`, `docs/specs/`, `docs/adr/`, `docs/invariants/`, `docs/gotchas/`, `docs/substrate/`, `docs/history/`) — prefer existing if present.
- **Validation enforcement.** `scripts/validate_plugin.sh` runs locally and in CI on push/PR via [`.github/workflows/validate.yml`](.github/workflows/validate.yml). A red check blocks merge — this is the structural fence that promotes the validator's checks (frontmatter shape, expected skill set, vocabulary tokens, fresh-eyes preamble, recommended-next footer, `PLUGIN_ROOT_PATHS`, `VERDICT_BEFORE_EVIDENCE`, voice-imperative pin in body prose, anti-citation lint on render templates) from "convention-with-script" to "convention-with-CI-enforcement." Canonical pin enumeration in [`PLUGIN_ROOT_PATHS.md`](docs/substrate/invariants/PLUGIN_ROOT_PATHS.md) §"Convention pins enforced alongside this invariant."

## Risks the design accepts

- **Discovery competition with Superpowers.** Both plugins have skills that look like discovery; the seam is documented in [`discovery-vs-superpowers.md`](docs/substrate/gotchas/discovery-vs-superpowers.md).
- **Soft prereqs may produce mediocre output.** When subskills are invoked without prior substrate discovery, output quality degrades. Detection pattern in [`soft-prereqs.md`](docs/substrate/gotchas/soft-prereqs.md).
- **Reviewer token budgets.** Token discipline is part of every reviewer agent's contract but is enforced by reviewer judgment, not structurally.
- **Behavior matrix template is unproven** until real-world matrices are produced from external repos.
- **Superpowers version drift in `implement-cohesively`.** The implementation pass names `superpowers:writing-plans` and `superpowers:executing-plans` explicitly. A future Superpowers rename or restructure breaks the pass. Mitigation is reviewer-judged compatibility checks during release.
- **Mega-plan abandonment on large deltas.** Single-pass implementation produces one writing-plans/executing-plans run; a delta with 30+ entries can overflow context mid-execution. Mitigated by the Step 1 delta-size budget gate (default threshold 15 entries) per [`docs/substrate/gotchas/large-delta-mega-plan.md`](docs/substrate/gotchas/large-delta-mega-plan.md).
- **Conventions over invariants.** Most v0.1 rules (chat-render header-depth cap, density budgets, forbidden phrasings, fresh-eyes preamble, router announcement, clarifying questions) live as convention, not enforced invariant. The rules that graduated to invariant — `PLUGIN_ROOT_PATHS` (a runtime correctness rule), `VERDICT_BEFORE_EVIDENCE` (the most-regressed UX rule with the cleanest grep), `IMPLEMENTATION_PLAN_COVERS_DELTA` (the structural pin behind the implementation pass), and `SKILL_DESIGN_DOC_SECTION` (the structural pin behind the per-skill design layer). Promotion is deliberate; convention status is intentional where wording is still settling.

## v0.1 scope

The plugin ships its workflow skills (per [`docs/substrate/architecture/skills.md`](docs/substrate/architecture/skills.md): subskills underneath the user-facing **Decide → Lock → Build** flagship gates, the off-chain diagnostics, the adoption skill `init` (the day-1 substrate bootstrapper added 2026-05-06; teaches the substrate vocabulary by translating proto-substrate signals from the user's own code), the router `cohesively`, and the session-start orientation skill `using-cohesive`), reviewer agents (per [`docs/substrate/conventions/reviewer-agent-shape.md`](docs/substrate/conventions/reviewer-agent-shape.md)), runtime references under [`references/`](references/), fillable templates under [`references/templates/`](references/templates/), architecture docs under [`docs/substrate/architecture/`](docs/substrate/architecture/) (three-tier-architecture, composition-with-superpowers, fresh-eyes-review, skills, handoffs), convention docs under [`docs/substrate/conventions/`](docs/substrate/conventions/) (skill-shape, reviewer-agent-shape, dispatch-protocol, skill-tool-dispatch, substrate-layout, audience-separation, scope), and the validator scripts under [`scripts/`](scripts/).
